# Quickstart — 驗證指南：M2 遺留缺陷與量測補強

**Spec**: [spec.md](./spec.md) ｜ **Plan**: [plan.md](./plan.md) ｜ **日期**: 2026-09-02

> 本規格的四類項目**全部不會報錯**。因此下列每一項驗證都要問同一個問題：
> **「如果這件事壞了，是什麼會變紅？」** 答不出來的驗證等於沒驗。

---

## 前置

```bash
npm run typecheck                 # nuxt typecheck + scripts/test 的 tsc
npm test                          # vitest（單元 + 對假 gateway 的整合測試）
npm run build && npm run smoke    # ⚠️ smoke 需先 build，兩支合計約 30 秒
```

⚠️ 本規格動到 `server/api/**`、`server/services/credentials.ts`、`server/services/session-manager.ts`，
依 `CLAUDE.md` 的規則 **MUST 一併跑 `smoke`** —— 它涵蓋 vitest 測不到的 HTTP route 與 cookie 往返，
並掃描每個回應確認憑證不外洩。

⚠️ 判讀任何 AI 相關數字前先跑 `npm run spike:agent-prompts`（約 1 秒）。
**量測數字是間接證據，快照 diff 是直接證據。**

## US1 — 雙分頁（SC-001／SC-002／SC-002a）

### 自動化（`npm test`）

| 驗什麼 | 壞掉時什麼會紅 |
|---|---|
| 同一客服兩條連線，關一條 → `borrowCredential()` 仍回傳 | 憑證單元測試 |
| 同一客服兩條連線 attach 同一對話，關一條 → session 未被刪 | session-manager 測試 |
| **`watchers.length === pipeline.refs`（三組情境）** | FR-004 的等式斷言 |
| 兩位不同客服，一位離開 → 另一位不受影響 | 既有行為不退步的測試 |
| 逾期登記不被 `borrowCredential()` 回傳 | 存活兜底測試（用假時鐘推進 45 秒） |
| **LEAVE 後該客服所有連線的面板同步消失** | SC-002a 的守衛（現況即應通過） |

⚠️ 最後兩列是**一對夾擊條件**，MUST 同時存在。
只驗「關分頁不影響其他分頁」時，把 LEAVE 與連線關閉合併的錯誤修法會通過測試。

### 手動（真實瀏覽器，stable 環境）

1. 同一帳號開兩個分頁 → 兩個都進同一段對話 → 關掉其中一個。
2. 從另一個帳號（或平台官方介面）對該對話送一則客戶訊息。
3. **期望**：留著的那個分頁在 4 秒內看到新訊息（§18 M1 的門檻）。
   對照現況：關閉其一即 100% 失聯。
4. 在留著的分頁送出一則訊息 → **期望**：不會閃一下重新插入（錨點有前推）。
5. 在任一分頁按「離開對話」→ **期望**：該帳號**所有**分頁的面板一起消失（SC-002a）。

⚠️ 步驟 5 要在步驟 1～4 之後做，因為它驗的正是「前面的改動沒有把 LEAVE 一起改壞」。

### 存活兜底的手動驗證

直接**斷網**或關掉瀏覽器行程（不是關分頁 —— 那會觸發正常的關閉事件）。
**期望**：45 秒後該筆登記被回收；若那是該組織最後一筆，第一層輪詢停止。
對照：少了 FR-005a 時，這筆登記會**永久**留著，而且是「用已登出的 token 繼續輪詢」。

## US2 — 恢復後補算（SC-003／SC-004）

### 自動化（`npm test`，對假 AI provider）

| 驗什麼 | 壞掉時什麼會紅 |
|---|---|
| 中段若干批失敗 → 新發言觸發 → 時間軸無中斷區間 | 補算整合測試 |
| 未涵蓋量很大時，單輪 ≤ 3 批（18 則） | 上限測試（斷言 AI 呼叫次數） |
| 補算失敗 → 停在 `error`，**MUST NOT** 自行再排一輪 | 003 SC-001 不退步測試 |
| **無缺口時，AI 呼叫次數與取歷史次數皆與現況逐一相同** | FR-012 的零成本測試 |
| 客服已 LEAVE → 不排入補算 | 003 FR-012 的既有測試 |
| **缺口的左界是 `timeline[0]`，不回頭補冷啟動視窗之前的訊息** | 左界測試（見下） |

⚠️ **左界那一條是本組最容易漏的測試。** 造一段長度超過 `DEFAULT_MESSAGE_LIMIT`（50）的對話，
冷啟動只涵蓋最近 50 則，然後製造一次失敗與一次恢復。
**期望**：補算只補「時間軸起點之後」的缺口，**不**回頭處理前面那幾百則。
漏了它的症狀是每一次新客戶發言都額外多打 3 批 AI 呼叫，直到對話結束 ——
測試全綠、畫面正常，只有帳單會知道。

### 手動（stable 環境）

需要能注入 AI 故障。若無法注入，退而求其次：
在真實對話上觀察一次自然失敗後的恢復，確認情緒折線沒有缺口區間。

## US3 — 引用品質（SC-005／SC-006）

### SC-005：三種成因分辨得出來

**驗收形式是事件，不是程式碼**（見 [contracts/citation-audit-event.md](./contracts/citation-audit-event.md)）：

```bash
# 跑一次分析，從標準輸出撈事件
npm run spike:progressive -- "某段真實對話標題" 2>/dev/null | grep suggestion.citation.audited
```

**期望**：每一次落定都有一筆 `suggestion.citation.audited`，
且 `outcome` 落在 `cited` / `no-hits` / `not-cited` / `discarded` 四值之一。
對任何一次「未引用知識庫」的卡片，由 `outcome` 即可判定成因，**不需重跑分析、不需讀程式碼**。

**額外落點的降級驗證**（FR-015a）：把落點指向一個**不可寫**的路徑並啟動服務。
**期望**：服務正常啟動、分析路徑不受阻斷、標準輸出的事件完整、stderr 有一行可辨識的原因。
⚠️ 這一條驗的是「開檔」失敗，不是「寫入」失敗 —— 要在**啟動前**就讓路徑不可寫。

### SC-006：杜撰率可重複量測

```bash
npm run spike:agent-prompts          # ⚠️ 先確認 prompt 未漂移
npm run spike:citation-quality -- <對話標題...>   # n=45 口徑
```

**期望**：產出整體杜撰率**與逐對話分布**，且改動封閉清單前後可比較。

⚠️ **本項不承諾 004 SC-002 的 80% 會提高**（spec 明文）。
最強的槓桿是建議卡 agent 的 system prompt 與選型，兩者都在 iMBrace 後台、不在本 repo。
量出來沒有改善**不代表本規格失敗** —— 交付物是「答得出為什麼」與「量得出來」。

## US4 — 並行度掃描與衛生（SC-007）

```bash
npm run spike:sentiment-concurrency        # 3／4／5 各三輪、n=45、輪換順序
```

**期望**：每一檔位同時產出**總時間分布**與**單次呼叫失敗率**兩列。

### 判準（FR-019，不得只看一列）

| 掃描結果 | 決定 |
|---|---|
| 總時間更短 **且** 單次失敗率未上升 | 採用，並把證據寫進正典文件 |
| 總時間更短 **但** 失敗率上升 | **MUST NOT 採用**，並把「總時間變快不足以作為理由」寫進文件 |

⚠️ **量測期間平台若處於已知降級時段，結果 MUST 標註時段**，
不得在降級樣本上下永久結論（2026-09-02 已經犯過一次）。

⚠️ **樣本 MUST NOT 並行取得** —— 並行度正是被量的變數。實跑約 1 小時，沒有壓縮空間。

⚠️ **15 秒 p90 門檻在本規格期間維持不動**（FR-020a）。
「掃描還沒跑就先改驗收標準」是被明文排除的做法。

### `user_id`（FR-021）

```bash
npm run spike:userid       # 驗證帶上 user_id 不會 400，且 id 多次取得一致
```

**期望**：既有分析行為完全不變，僅少一趟往返（實測值 54ms）。

## 全域不退步（SC-008）

```bash
npm run typecheck && npm test && npm run build && npm run smoke
```

⚠️ `smoke:realtime` 會量**實際延遲**並斷言 ≤ 4 秒。機器負載重時它可能浮動 ——
**但失敗是真的訊號**，不要因為「偶爾紅」就放寬門檻，那個數字是驗收標準本身。

001～004 的既有驗收全部維持通過，特別是：

- 003 SC-001（AI 不可用時 10 分鐘內不超過 1 輪）—— 補算最容易踩爆的一條
- 003 T032a（主動離開對所有分頁生效）—— US1 最容易改壞的一條
- 004 的靜默行為（第二段失敗不重試、不閃重試中、不轉 error）
