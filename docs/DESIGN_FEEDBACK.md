## B. 請勿回退

> 這一段**沒有待辦**。列出來是因為這些位置很容易在下一輪設計時被善意地「補回去」或「調回去」，
> 而改回去之後我們只能再拿掉一次。

### B-1　畫布畫得到、但平台資料拿不到

| 位置 | 現在的畫法（正確） | 為什麼不能放回原本的樣子 |
|---|---|---|
| 客服身分（頂列／presence／訊息泡泡） | **email**（`agent.lin@company.com`） | 平台沒有人名：登入回應沒有 `display_name`／`name`，團隊名冊 `display_name` 實測 12/12 全是 email。我們**不會**從 email 反推姓名——同名同姓、共用信箱、非英文名字都會產生錯的名字，而認錯同事正是撞單防護與 presence 最不能出錯的地方 |
| 左欄列項第二行 | 頻道 icon ＋ presence 標記 | 對話清單的 payload 沒有「最後一則訊息」的文字或發送者，要顯示就得對每一列各打一次訊息 API |
| 「N 則」數字 | 不帶總數的措辭 | 訊息 API 只回一頁 ＋ `hasMore`，沒有剩餘則數；組織清單也沒有進行中對話數 |
| 客戶輸入狀態 | **沒有這個元件** | 平台不提供。假造一個比沒有更糟——客服會為了等一個不存在的訊息而停手 |
| AI 訊息 meta | 只有時間（到秒） | 訊息 payload 沒有意圖與信心欄位；到秒是因為撞單判斷靠的正是秒級先後 |
| 未讀 | **圓點** | 我們的新訊息訊號在一次輪詢間隔內來幾則都只跳一次，數出來是「批次數」不是「則數」 |

### B-2　為了無障礙而定的兩個 token

| token | 決定 | 為什麼不能調回去 |
|---|---|---|
| `--open` | 淺色為 `#8a5d05`（曾為 `#a3700a`） | 舊值疊在 `--open-bg` 上只有 **3.87:1**，過不了 WCAG AA 內文的 4.5:1。這個 token 用在摘要過期提示、知識庫過期註記、`open` 狀態標籤、「挽留」語氣標籤 —— **每一處都是文字**，調亮會同時破線 |
| `--info` | 淺 `#20406f`／深 `#9dc0f2`，專供 `--navy-soft` 底上的文字 | ⚠️ **不要改成直接調亮 `--navy-2`** —— 它同時是按鈕的 hover 底色，調亮會讓按鈕上的白字失去對比。分成兩個 token 才能各自最佳化 |

> 五種語氣標籤在兩個主題下的對比我方都實算過，十組全部通過 AA（最低 5.17:1）。
> 數值見 `docs/DESIGN_TOKENS.md` §10。

## C. 實作刻意與畫布不同（告知，不必改畫布）

> 這些是我方**已裁示**的選擇，列出來是為了讓下一輪核對時不會被當成「實作沒跟上」。
> ⚠️ 編號留缺不遞補（C-1～C-4、C-7～C-9 已解決或已納入畫布），以免與先前轉出的版本對不上。

| # | 項目 | 畫布 | 實作 | 理由 |
|---|---|---|---|---|
| **C-5** | **服務模式說明** | 「模式是這個對話的共用設定，切換會影響所有人。」 | 句末多一句「**，包含在 iMBrace 官方介面工作的同事**」 | 我們的鎖只在 AgentCopilot 內有效，這個邊界必須講清楚 |
| **C-6** | **拖曳把手的鍵盤操作** | 只畫滑鼠拖曳 | `role="separator"` ＋ 方向鍵／Home／End | 5px 的線對只用鍵盤的人等於不存在 |
| **C-10** | **字級** | 逐項 px 值 | 全面加大約 **2.5px**，並由固定 px 改為 `rem` | 使用者分兩輪確認過的調整；`rem` 也讓瀏覽器／OS 的字級偏好能生效。**相對關係與 weight／letter-spacing 完全照畫布** |
| **C-11** | **情緒走勢圖尺寸** | `viewBox="0 0 128 34"` 靠右 | **整欄寬** | 要放最多 50 個評分點 ＋ 附件標記，128px 下每點只剩 2.5px |
| **C-12** | **頭像下拉裡的 email** | `text-overflow:ellipsis; white-space:nowrap` | 等寬字**允許換行、不截斷** | 那是要逐字核對「是不是我的帳號」的東西，而截斷正好蓋掉最能區分帳號的網域部分 |
