## B. 請勿回退

> 這一段**沒有待辦**。列出來是因為這些位置很容易在下一輪設計時被善意地「補回去」或「調回去」，
> 而改回去之後我們只能再拿掉一次。

### B-1　畫布畫得到、但平台資料拿不到

| 位置 | 我方的畫法 | 為什麼不能放回原本的樣子 |
|---|---|---|
| 客服身分（頂列／presence／訊息泡泡／涵蓋範圍候選列／**唯讀區「參與的客服」**） | **email**（`agent.lin@company.com`），多人以「、」串接 | 平台沒有人名：登入回應沒有 `display_name`／`name`，團隊名冊 `display_name` 實測 12/12 全是 email。我們**不會**從 email 反推姓名——同名同姓、共用信箱、非英文名字都會產生錯的名字，而認錯同事正是撞單防護與 presence 最不能出錯的地方。⚠️ 也**不要退回顯示原始 `u_` id**：那串字對客服不對應任何他認得的東西，而這一格要回答的正是「誰服務過這位客戶」。✅ 畫布已於前兩輪把中文人名與原始 id 都改成 email，全畫布現在一致 |
| 左欄列項第二行 | 頻道 icon ＋ presence 標記 | 對話清單的 payload 沒有「最後一則訊息」的文字或發送者，要顯示就得對每一列各打一次訊息 API |
| 客戶輸入狀態 | **沒有這個元件** | 平台不提供。假造一個比沒有更糟——客服會為了等一個不存在的訊息而停手 |
| AI 訊息 meta | 只有時間（到秒） | 訊息 payload 沒有意圖與信心欄位；到秒是因為撞單判斷靠的正是秒級先後 |
| 未讀 | **圓點＋「未讀」** | 我們的新訊息訊號在一次輪詢間隔內來幾則都只跳一次，數出來是「批次數」不是「則數」 |
| 空狀態的「只看未回覆」 | **沒有這顆按鈕**（1d） | 對話清單的 payload 沒有「最後一則訊息是誰送的」，篩不出「未回覆」；要做就得對每一列各打一次訊息 API |
| OTP 錯誤的「還可嘗試 N 次」 | **不顯示次數**（1a） | 驗證 API 沒有剩餘次數欄位，數字只能用猜的：猜多了客服以為還有機會、下一次就被鎖；猜少了他在還能試的時候放棄 |

### B-2　為了無障礙而定的兩個 token

> ✅ 兩者畫布都已採用（`--open:#8a5d05`／`--info:#20406f`／深色 `#9dc0f2`），
> 與實作逐字相同。保留本節**只為了防回退**。

| token | 決定 | 為什麼不能調回去 |
|---|---|---|
| `--open` | 淺色為 `#8a5d05`（曾為 `#a3700a`） | 舊值疊在 `--open-bg` 上只有 **3.87:1**，過不了 WCAG AA 內文的 4.5:1。這個 token 用在摘要過期提示、知識庫過期註記、`open` 狀態標籤、「挽留」語氣標籤 —— **每一處都是文字**，調亮會同時破線 |
| `--info` | 淺 `#20406f`／深 `#9dc0f2`，專供 `--navy-soft` 底上的文字 | ⚠️ **不要改成直接調亮 `--navy-2`** —— 它同時是按鈕的 hover 底色，調亮會讓按鈕上的白字失去對比。分成兩個 token 才能各自最佳化 |

> 五種語氣標籤在兩個主題下的對比我方都實算過，十組全部通過 AA（最低 5.17:1）。

### B-3　兩處刪掉之後不要再加回來的東西

| 位置 | 曾經有、現已移除 | 為什麼不能加回來 |
|---|---|---|
| B8「回報成功但紀錄不存在」 | 「重試可能產生重複紀錄，確認後再按。」 | 實測（`spike:board-write` 006-E10）建立後 47～55ms 即可被搜尋到、`getItem` 3/3 立即可取，因此重試會命中既有紀錄走更新，**不會產生第二筆**。⚠️ 提示說會出事、實際不會，客服因此不敢按一個其實安全的操作 —— 這比沒有提示更糟 |
| 2b 按鈕列 | 次鈕「標記為已手動建檔」 | 它代表 Board 上要不要為此留一筆，而那牽涉第二條寫入路徑與「CRM 一筆 ＋ Board 一筆」的重複問題，超出 `specs/006` 範圍。⚠️ 日後要重啟，**重啟條件是先決定 Board 端的語意** —— 不留「文案先於行為」的帳 |

## C. 實作刻意與畫布不同（告知，不必改畫布）

> 這些是我方**已裁示**的選擇，列出來是為了讓下一輪核對時不會被當成「實作沒跟上」。
> ⚠️ 編號留缺不遞補，以免與先前轉出的版本對不上。
> C-19 ～ C-38 每一條都在 2026-09-08 對 14:31 版畫布重驗過，畫布側維持原樣，十二條仍然成立。
> ⚠️ 本輪**沒有新增**任何偏離。

| # | 項目 | 畫布 | 實作 | 理由 |
|---|---|---|---|---|
| **C-19** | **情緒示警 pill 的文案** | 逐字「焦慮偏高」 | 「客戶情緒：挫折」／「客戶情緒：生氣」 | 我方是**五級分類**（平靜／普通／擔憂／挫折／生氣），畫布只示範了其中一種情況的措辭。規格（001 FR-003）要求「挫折」與「生氣」在文字上就能互相區分 |
| **C-22** | **走勢摘要的強調** | 整段同一色、無強調 | 後半的「建議…」加粗 | 客服真正要用的是那一句；走勢那半在折線圖上已經看得到 |
| **C-25** | **走勢圖的筆畫縮放** | `stroke-width:2`（畫板固定 420px，無 `vector-effect`） | 加 `vector-effect="non-scaling-stroke"` | 畫布的畫板寬度固定，我方的面板**可拖曳 320–720px**。等比 viewBox 之下筆畫會跟著放大，720px 時那條 2 的線會被畫成約 4px。加上之後幾何仍完全等比、線寬固定為畫布給的值 |
| **C-27** | **左欄列項的頭像配色** | 一律 `--surface-3` 單一灰 | **六色輪替**（依代號雜湊） | 讓客服在長清單裡能用顏色快速定位同一個對話。⚠️ **但訊息泡泡裡的客戶頭像維持畫布的單一灰**：色盤裡有一組是 `--ai-bg`／`--ai`，而在訊息流這個畫面裡 `--ai` 是語意色（「這則是 AI 發的」），用它畫客戶頭像等於讓同一個顏色講兩件相反的事。畫布自己的示範代號 `TWN#GW4772` 雜湊後正好落在那一組 |
| **C-28** | **左欄「載入更多對話」** | spinner 自動載入列 | **可按的按鈕** | 自動載入會在客服往下捲時持續打 API 且無法中止；載入時機交給人決定 |
| **C-29** | **左欄搜尋列** | 只有搜尋框 ＋ 收合鈕 | 多一顆重新整理鈕 | 輪詢有間隔，客服偶爾需要立刻確認清單是最新的 |
| **C-30** | **未接手時的輸入區** | 虛線提示框取代整個輸入區 | **只有「尚未接手」這一種**照畫布 | 另外兩種不能送出的情況（Automation Only 唯讀、同事鎖）維持「說明框 ＋ 停用的輸入框」：那兩者是**暫時**狀態，客服可能想先把草稿打好，而畫布沒有涵蓋它們 |
| **C-31** | **連續訊息的分組條件** | （畫布只示範連續兩則 AI） | 只看**發送者**，不看時間間隔 | 平台的訊息時間戳在同一批可能相同或極接近，加上「N 分鐘內才算同一組」會產生不穩定的分組。⚠️ 真人客服另比 `sender.id`——只看 `type` 會把兩位同事的連續發言併成一組，第二位的 email 就此消失 |
| **C-32** | **輸入框高度的下限** | 兩行 `72px`（副標逐字「兩行 72px – 320px」，鍵盤說明也寫「最小為兩行」） | 一行 **`46px`**（預設仍是 `72`） | 小螢幕筆電上，72px 的下限會把訊息流壓到看不到幾則，而客服真正在讀的是訊息流。46 ＝ 一行 `16px × 1.6` ＋ 上下 padding 各 10px。⚠️ 原本訂在兩行的理由（「再低會讓 Shift+Enter 換行看起來像壞掉」）改由 `rows="1"` 承擔 —— 一行是誠實的一行，不是被切一半的兩行。⚠️ **只動下限，不動預設**：多數螢幕上兩行仍是對的起點，高度會存進 `localStorage`，需要的人拖一次就記住 |
| **C-35** | **摘要「詳細內容」四段的內文** | 每一段是一整段文字 | **項目符號 `<ul>`** | `keyFacts`／`attempted`／`openIssues` 在我方是**字串陣列**，攤平成一段會失去「這是幾件獨立的事」—— 客服掃的時候要能一眼數出還有幾項沒解決。⚠️ 段標、字級與間距全部照畫布，只有內文改成條列 |
| **C-37** | **§7.4「五塊的來回」（進入結案前的收合／捲動位置，取消後原樣還原）** | 有此行為（2b 的「決策 · 其餘五塊的來回」說明卡仍寫著） | **不實作** | 我方的第 6 區塊是以 `v-if` 切換版面的，其餘四塊在進入結案時會被**卸載重掛**，內部狀態不是「被覆蓋」而是「不存在了」。要還原就得先把每一塊的展開狀態提到頁面層集中管理，那是一次跨五個元件的改動，效益（少按一次展開）不成比例 |
| **C-38** | **§7.5 涵蓋範圍選擇器的三種呈現風格（`quiet`／`row`／`list`）** | 三種（`scopeStyle` 仍宣告三個 enum 值，預設 `row`） | **只出貨 `row`** | 另外兩種在本期沒有任何畫面用得到。要補另外兩種時，連同呼叫端一起加回來 |

## 本輪移除了什麼（2026-09-08 第五輪重核）

⚠️ 記在這裡是為了讓收到前一版的人知道「那一條去哪了」，**不是變更沿革**；
下一輪重核時本節可整段刪除。

**因 Design 採納我方做法而移除：**

- **C-41　唯讀區「參與的客服」**：畫布把 `sysAgents` 從原始 id
  `u_df56079c-7df4-41c6-9ce0-5f57f29df534` 改成
  `agent.lin@company.com、agent.chen@company.com` —— **連多人的分隔符「、」都與我方相同**
  （我方是 `operatorLabels.join(、)`）。示範值同時從一人變成兩人，
  正好也把「多人時長什麼樣」定義了下來。不再是偏離。

  ⚠️ 唯一要記住、但**不屬於畫布**的一件事：**寫進 Data Board 的 `operators` 仍是 id**。
  id 穩定，email 會隨帳號改名變動，改完之後舊紀錄就指不回任何人；
  這也與 `reviewed_by` 存 id 的既有做法一致。畫面顯示名字、儲存用 id，兩者刻意不同。
  （同一條原則也適用於上一輪的時間格式：畫面本地時區、Board 與後端日誌存原始 UTC ISO。）

**本輪的畫布改動就只有這一處** —— `template.html`（1a／1b／1c／1d／3a）與上一版
逐位元組相同，`CopilotPanel.dc.html` 也只有 `sysAgents` 那一行不同。
B 段的每一列與 C 段的十二條都逐一重驗過，沒有回退。
